# G2.3 侧边栏 MVP 与本地验收

## 本轮交付

保留字幕、概览、笔记、翻译、划词解释和跳转，新增第四个“目标导航”。沿用原有
sidepanel.css token，未重设计或引入依赖。MIT 与上游声明保持原样。

UI 顺序：当前视频/目标输入 → 推荐路径 → 卡片内可折叠原始证据 → 子目标覆盖/缺口/
站内搜索 → 可折叠的既有章节建议与调试。watchOrder 决定 AI 卡片次序，字幕仍按时间排列。
关键词模式只标为词法匹配，不声称是 AI 学习路径。证据不足不会填充至3条。

概览改为显式“生成 AI 概览”，打开标签不再自动请求。每次切视频回到原文字幕，翻译仍由
用户点击中文/双语控制触发；Goal 不调用这些旧功能。普通字幕加载也只读取B站字幕，不进入
ASR。旧ASR实现未扩展，Goal没有ASR入口。

## 文件与接口

新增 `goal/controller.js`（交互与异步状态）、`goal/view.js`（原生DOM）、
`goal/cache.js`（版本化缓存）、`tests/goal-panel.test.js`、`DESIGN.md` 和本文档。
修改 sidepanel.html/css/js 接入模块，content.js 增加受身份约束的 goalSeek，options.js
清理缓存时一并清理 goal_result_。goal/navigator.js 暴露已有严格校验器 validateResult
供缓存回读重建。background.js 增加安全跳转及仅包含实际usage的遥测回调。

消息链：

1. 页面识别当前窗口内活动B站tab，读取元数据；导航/重载/切tab即失效旧状态。
2. 提交时 `fetchGoalTranscript({tabId,bvid,page})` 注册新鲜快照（ASR关闭）。
3. `checkConfig` 只返回Key是否存在与模型名，不向UI返回Key。
4. 无Key：G2.1 `createIndex(snapshot).search(goal)` → 本地卡片与可跳转原始cue。
5. 有Key：SHA-256缓存键查找并严格重建/校验，命中直接展示；未命中才 `analyzeGoal`。
6. G2.2单次调用后返回watchOrder/覆盖/缺口，原文与时间由本地证据回填，保存有效缓存。
7. 跳转发 `goalSeek({tabId,identity,seconds})`：后台核对已注册hash、tab URL、实时CID和真实cue
   起点，content核对当前BVID/分P/播放器。无“任意B站tab”回退；成功后切到字幕并定位目标行。

每个显示任务绑定当前tab、BVID、CID、page、hash和requestId，generation在异步等待后再次核对。
相同BV不同tab也会清理旧状态。字幕分组保留原始cue索引，映射成cueId后用独立的
`goal-recommended`类和“目标推荐”标签；不改`active-playback`，不使用字符插值时间作证据。

`GoalPanelController.createController({send,storage,onChange,isCurrent,seek})` 提供
`setContext/submit/jump/clear/getState/getSnapshot`，可在Node Mock中复现。
`GoalPanelView.mount(...)`只处理DOM，不调用模型。G3可在现有GoalAiProvider契约后扩展Hosted，
UI仍通过analyzeGoal使用结果；届时必须将模式/模型/Prompt版本加入缓存键，不在扩展放开发者Key。
本轮没有Hosted、支付、账户、跨视频或自动播放实现。

## 缓存与诊断

缓存键覆盖视频身份、字幕hash、trim后目标、模型、分析/Prompt版本。键使用SHA-256，不直接
包含问题。默认7天、最多20条、约1.8MB预算；写入失败仍显示结果。失效缓存重建，读回不信任
保存的时间/正文/链接，重新从当前快照与合法候选生成。有效命中不会调用模型。

缓存保存分析结果（含引用字幕与子目标），这是功能数据，不是调试日志。设置页“清理摘要缓存”
会同时删除digest_和goal_result_。输入草稿只留内存；清除目标清掉显示状态，不删除所有缓存。

“本次请求调试”显示耗时、缓存命中、是否发生模型请求及实际prompt_tokens/completion_tokens。
服务未返回usage时显示“未知”；缓存命中不冒充本次产生Token用量。网络中断导致无法确认是否
送达时模型请求显示未知。没有持久调试日志，不保存Key、完整问题或完整字幕到调试日志。
模型失败仅手动重试；无Key仍可用本地检索。重复点击共享同一进行中任务。

## Chrome 本地安装

1. 把整个仓库下载/检出到固定目录，确认根目录有manifest.json、goal/、ai/和prompts/。
   不需要npm install或构建；不要只复制旧版本文件，新增目录也必须完整。
2. Chrome 116+ 打开 `chrome://extensions/`，打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择**包含manifest.json的项目根目录**。
4. 若已加载旧版本，在同一目录更新文件并点击“重新加载”；不要卸载，以免丢失本地Key/笔记。
5. 刷新已经打开的B站视频，避免使用旧content script。点击页面“AI总结”或扩展图标打开侧栏。
6. 扩展显示名仍是Bilibili Digest，第四标签为“目标导航”；本轮不进行品牌整体替换。
7. 先在干净Chrome个人资料中不配Key验证免费流程。不要把无Key和无字幕混为一谈：视频必须有
   账号可读取的B站字幕，部分AI字幕需要先登录B站。

## 配置 DeepSeek BYOK

点击侧边栏“设置”（或无Key提示中的API设置入口），在原设置页填写自己的DeepSeek API Key，
点击保存，确认读回验证成功。无需百炼Key。返回目标导航重新提交即可重新检测配置。
不要把真实Key贴入聊天、截图、Issue或调试控制台。

当前沿用settings.js默认模型`deepseek-v4-flash`。真实可用性、账号权限和额度由DeepSeek决定；
本轮没有使用真实Key确认该模型服务。401时检查Key；429时等待后手动重试，不自动循环。

## 至少三类手动视频验收

选择你有权观看、带可读字幕的公开视频，记录实际BVID/CID/分P、版本、结果及缺陷；不需要
预先依赖某个可能失效的视频链接。

| 视频类型 | 目标示例 | 重点预期 |
|---|---|---|
| 技术对比/讲解视频 | LangGraph和CrewAI有什么区别？ | 无Key先显示关键词证据；有Key优先比较论据，理由对应原字幕，不保证完整答案 |
| 长教程/实操视频 | 我想做一个长期记住用户偏好的Agent | 区分前提、方法、示例和限制；路径可非时间排序，不能仅因提到术语就宣称教程完整 |
| 非相关主题视频或完全无字幕视频 | 在烹饪视频里寻找Agent部署方法 | 无Key应为空匹配；AI可能给uncertain/not_found，不得宣称全视频绝对没有；无字幕直接报错，不启动ASR |

每类都执行：

- 无Key输入目标，用Tab/Enter操作提交和证据折叠；点击时间核对播放器到真实cue起点。
- 配Key后生成一次路径，对照watchOrder、卡片顺序、理由、子目标覆盖与搜索词。
- 点击卡片跳回字幕，确认“目标推荐”标记与“当前播放”高亮能共存。
- 展开已有章节建议时不产生额外模型请求；无章节时明确提示，不能把召回冒充结构。
- 原样重提目标应命中缓存；改目标应重分析；展开证据/切标签/高亮不应增加请求。
- 在分析中切BV、切同BV的P2、切另一个B站tab、关闭/刷新原tab，确认旧结果不出现在新视频。
- 连点提交、制造断网/无效Key/限流，确认不自动重试，用户能看懂并手动恢复。
- 检查字幕浏览、手动AI概览、笔记、翻译、划词解释和旧时间戳跳转。

打开补充搜索应只到真实B站搜索页；搜索结果未经系统验证，不是已验证视频推荐。

## 查看用量、错误与记录缺陷

在“目标导航”底部展开“本次请求调试”。若需检查网络，在扩展管理页点击service worker的
“检查视图”，只查看请求数量、状态及usage；不要截图/导出Authorization、完整请求体或字幕。
平台重启、模型无usage或请求未完成时，显示未知是正确行为，不应写成0Token。

缺陷记录建议：扩展版本/提交、Chrome版本、BVID/分P、是否登录、Key是否配置（只记录是/否）、
目标类型（可脱敏）、预期与实际卡片/时间、错误类型、请求次数、缓存标记、是否复现。
不要附真实Key、Cookie、私密字幕或个人问题原文。

## 尚未完成与限制

当前云环境管理策略禁止加载未打包扩展，因此真实Chrome扩展/B站/真实模型验收待本地执行。
