# G3 需求方案：预付余额与实际 API 用量计费

> 状态：仅需求设计，未进入开发或部署。与根目录 PRD V1.1 配套；计费公式和产品规则以 PRD 为准。G2.1–G2.3 实现、测试记录及局限保持不变，不将本方案描述成已上线功能。

## 范围与依赖

小豆集市自动发放一次性充值码，暂定 ¥5/¥10 等额入账；Workers 安全保存开发者 Key、调用模型，D1 管理余额和账本。免注册许可证恢复钱包；保留本地历史及导入/导出备份需求。BYOK 不经过付费链路，GoalClip 服务费为零。无自有域名、固定付费服务器、独立支付页、账号或订阅系统。

先确认平台允许 AI 服务预付额度、主体与售后条件；通过大陆网络、内容获取与 AI 服务准入门槛后方可公开收费。免费额度耗尽安全停止新调用，不自动购买资源。

## 产品原则与收费单位

准确、可追溯且符合目标的观看路径优先。保证足够证据、上下文、输出空间和理由，不为减少 Token 机械压缩候选。使用本地检索、缓存、去重及按需调用节约成本；预算不足则提示提高预算或缩小范围并重确认。

一次分析任务可有多次底层调用，每次成功调用收费：

`API 实际成本 + max(API 实际成本 × 10%, ¥0.10)`

最低 ¥0.10 是每次 GoalClip 服务费，不是支付手续费。多次调用分别计算最低服务费，任务预算包含所有费用。缓存命中显示 ¥0，无模型请求、无服务费。

## 估价、确认和接口要求

先根据实际构建的待发送消息规模、模型计数方式、预计输出量、价格版本及预计调用计划估价，展示估算依据、预计 API 成本/服务费/总额，以及单独的人民币最高扣费。预估不能用固定价格代替，不得为估价调用收费模型。

`POST /v1/analysis/estimate` 返回估价 ID、内容/范围指纹、模型计划、价格版本、Token 估算、费用分项、建议上限和有效期。估价仅用于展示与预留，不作实际结算依据。

`POST /v1/analysis` 必须携带有效估价 ID、明确确认的预算、任务幂等 ID；服务端校验估价归属与未变更的任务范围。未确认、估价过期或影响价格的输入/模型变化时，不得开始付费模型调用。

`POST /v1/analysis/:id/budget` 仅在展示新估价及新增授权总额并明确确认后追加预算。查询任务与账单不触发新模型请求。其余 API 与 D1 字段见 PRD 第 8 节。

## 账本与金额规则

整数 micro_cny（¥1 = 1,000,000），整数有理数保存价格，禁止浮点金额。以供应商实际返回并关联请求 ID 的输入、输出、缓存读写 Token 或可核验单请求账单结算，按供应商口径去除缓存重复计价。模型价格、币种、汇率、折扣和舍入采用服务端不可变版本，客户端不能指定收费数据。

先计算未取整 API 成本 C；API 入账 `ceil(C × 1,000,000)`，服务费入账 `ceil(max(C × 10%, 0.10) × 1,000,000)`，逐次相加。价格、汇率和优惠口径需销售前定稿。展示实际精度，不能把 ¥0.102 隐为 ¥0.10。

无可靠 usage、缓存分类缺失、供应商请求对应关系不明等情况进入待核账；不能以字符、tokenizer、预估价或账户总账分摊猜测扣费，也不能将未知当零 Token 成功结算。

账本追加充值/预留/结算/释放/退款/调整记录，唯一事件键防重放，反向分录纠错。钱包可用余额 = 总余额 − 预留，任何并发不得透支。充值码只兑换一次，许可证才是跨设备恢复凭证；备份不能改写余额。

## 状态机与恢复要求

- 任务：待估价 → 待确认 → 已预留 → 执行中 → 完成/部分完成/取消/失败/待核账 → 释放未用预留。需要追加预算时停在等待确认，不能继续调用。
- 调用：已分配预算 → 已发出 → 已验证结果与用量 → 已交付/可恢复 → 已结算；超时、未知用量或丢失响应进入待核账，明确失败进入不向用户收费的释放路径。
- 任务预留包含各次调用子预算，不能重复增加钱包预留。每次发出前校验剩余授权可覆盖该请求最大输入/输出费用及服务费，设并发、单次、任务、每日供应商费用和请求速率上限。
- 任务/调用/账本幂等键持久化；同 ID 同内容返回原状态，不重复请求；同 ID 不同内容拒绝。真正重试生成可追踪的新调用，但仍受原任务预算限制。
- 数据库原子操作与外部模型调用分离，以状态机恢复中断。未知是否发出的请求不盲目重发；优先按供应商请求 ID 查账，避免双重模型成本。

## 失败、交付与补偿

成功收费须同时有可靠实际用量、该调用格式/证据验证成功和可靠交付。中间有效调用可独立结算，任务后续失败时逐次告知此前成功费用，此边界事前公示。

失败但上游收费暂定由 GoalClip 承担，该调用用户 API 费/服务费均为零。上游已扣费但响应丢失/结果未交付时，先按原任务 ID 免费恢复结果；无法恢复或超交付截止时间则不收费，已扣部分全额反向退回 API 费和服务费。不能以“上游收费”作为无结果自动扣费理由。

可靠结果恢复仅允许最小必要、加密且有明确短期 TTL 的任务输出/状态，不记录完整字幕或敏感对话；交付确认后按保留策略清理。若隐私约束不允许保留结果，必须接受不可恢复时退款，不以内容保留换取强制收费。具体 TTL 和交付确认方式销售前决定。

未知用量在核账截止前可凭可靠记录结算；逾期仍不可靠，由 GoalClip 承担并释放，不追扣。重试、取消、格式修复、无证据及部分失败按 PRD 第 9 节处理。系统限制异常造成超过授权上限的差额由 GoalClip 承担。

核账、交付和退款时限上线前配置并公示。支付渠道成本不暗扣充值余额。退款按订单及账本核查，保留证据，不覆盖历史分录。

## G3 后续开发验收清单（本轮不执行）

1. 未确认时无付费模型请求；估价可解释且随实际消息规模、价格和预计输出变化，明确预估/最高/实际金额。
2. PRD 六个费用例子及两次 ¥0.02 调用合计 ¥0.24 通过；缓存和 BYOK 无服务费。
3. 成功后逐次展示实际输入/输出/缓存 Token、API 成本、服务费及最终扣费，任务总额不超确认上限。
4. 用量未知或不可靠不估算扣费；上游收费失败、未交付、超时核账有明确零收费或全额退款路径。
5. 重复兑换/请求/回执/退款、并发与 Worker 中断恢复不重复扣款，账本可重建余额，预留可释放。
6. 许可证跨设备恢复，历史及备份导入/导出不触发模型或改写余额，默认不导出密钥。
7. 预算不足不静默削弱证据；人工样例验证关键片段、理由、覆盖和不确定性，全部引用可追溯真实 cue 与时间。
8. 开发者 Key 不进入扩展/日志，客户端不能篡改价格或访问其他钱包；限流和支出上限生效。
9. 保留 G2 本地检索、严格证据校验、缓存、跳转、高亮、旧功能与现有验收限制，不能把 Mock 当真实商业链路验证。
