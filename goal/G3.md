# G3 需求方案：预付余额与任务级实际 API 用量计费

> 状态：仅需求文档，未进入 G3 开发或部署；与 PRD V1.1 一致。G2.1–G2.3 代码、功能及验收记录保持不变。

## 范围与依赖

沿用小豆集市自动发卡 + Workers/D1 免费额度：暂定 ¥5/¥10 充值码兑换等额人民币余额；开发者维护模型 API 与账单，Key 仅存 Workers Secret。保留免注册许可证恢复余额、本地历史及导出/导入备份要求，BYOK 无 GoalClip 服务费。不建账号、订阅、独立支付页，不买自有域名或固定付费服务器。

**V1 默认单次 LLM 调用。多调用仅是后续可扩展设计，未经确认不纳入 V1/G3 开发范围。快速、标准、深度三种模式待决策，不是已批准功能，不要求 V1 实现选择器或模式字段。** 本文多调用算例和数据关联仅用于验证规则兼容性，不授权开发相关执行能力。

公开收费前通过平台商品准入、主体、内容读取、AI 服务适用要求和大陆网络门槛；免费资源耗尽安全停止新调用，不自动购买资源。

## 质量与任务计费原则

准确、可追溯、符合用户目的的观看路径优先。保证充分证据、上下文、输出空间和推荐理由，保留引用验证、覆盖判断和不确定性提示。成本优化采用本地检索、去重、缓存、按需调用及避免重复请求，不机械压缩 Token；预算不足提示提高预算或缩小范围并重新确认。

**任务总扣费 = 本任务实际 API 成本合计 + max(本任务实际 API 成本合计 × 10%, ¥0.10)。**

本任务合格 API 成本 C 的纳入规则见“失败与补偿”。任务所有合格调用成本先汇总，再计算一次服务费，不能每个底层调用叠加 ¥0.10。最低金额是 GoalClip 每个收费任务的服务费，不是支付手续费。底层用量仅作成本明细，不独立扣款。

任务由任务 ID、目标、内容范围和最高预算授权确定；重连、查询、恢复、追加预算不新建收费任务。用户明确发起并确认新的目标分析才创建新任务。缓存命中无实际模型请求时扣费 ¥0、服务费 ¥0；实际发生请求、可靠用量确认成本为零且成功交付时按公式收一次 ¥0.10，不能将未知用量当零成本。

## 任务估价、授权与接口

预估基于实际待发送消息规模（含系统提示、目标、证据和必要上下文）、模型计数方法、价格版本和预计输出量，不用固定价格冒充估价，也不为估价发起收费请求。先合计预估 API 成本，再计算一次任务预估服务费。清楚区分人民币预估费用、最高扣费、实际扣费，未明确确认不开始付费分析。

- `POST /v1/analysis/estimate`：返回任务估价 ID、范围指纹、模型计划、价格版本、Token 估算依据、任务 API 预估合计、一次服务费、预估总额、建议最高额和有效期。
- `POST /v1/analysis`：验证估价归属、范围及有效期，携带任务幂等 ID 和明确授权的最高额；按任务预留并执行默认单次请求。
- `POST /v1/analysis/:id/budget`：追加预算需重估并确认新的任务最高总额，不创建新的最低服务费；不隐含批准增加调用。
- `GET /v1/analysis/:id` 与 `/v1/billing`：任务状态、任务费用三项和可展开的调用 Token/成本明细，查询不触发模型请求。充值及钱包 API 见 PRD 第 8 节。

用户输入、范围或计划外影响价格的模型/价格变更须重新确认。未来多调用若批准，原授权计划内中间上下文不视为用户改目标，仍受同一任务上限约束。

安全预留按最坏任务 API 合计加一次服务费计算；未来每个新请求前将已发生成本、下一请求及剩余计划最大 API 成本合计，再计算一次服务费后对比任务上限，不能将每调用最低服务费相加。实际任务扣费不超授权，系统异常超额由 GoalClip 承担。

## 金额、数据与账本

整数 micro_cny，¥1 = 1,000,000，价格用整数有理数，禁止浮点金额。每个底层请求记录供应商实际输入/输出/缓存读写用量、请求 ID 和服务端不可变价格版本；按模型真实口径去重缓存成本。币种、汇率和折扣均可追溯，客户端不能指定价格或费用。

先以未舍入有理数汇总本任务合格成本 C：任务 API 入账 `ceil(C × 1,000,000)`，一次任务服务费入账 `ceil(max(C × 10%, 0.10) × 1,000,000)`，任务总额为两项之和。不先逐调用舍入再合计，不对先舍入 API 金额再算服务费。缓存/失败零收费按特例处理。展示真实精度，不能隐藏 ¥0.102。

可靠数据只能来自服务端收到且关联请求 ID 的供应商 usage 或可核验单请求账单。缺失、分类不全或不可对应的用量进入待核账，不使用字符、tokenizer、预估价、账户总账分摊猜测扣费。

数据库与 PRD 第 8 节一致：

- `tasks` 存任务授权、预留、API 合计、一次服务费、最终扣费和状态。
- `estimates` 存任务级估价与确认依据，不存完整输入，V1 不要求模式字段。
- `model_calls` 仅存调用用量、未舍入成本分子/分母、计费资格及对账状态，无独立用户扣费或服务费字段。
- `ledger` 追加充值、任务预留、任务结算、释放、退款和调整。用户结算及服务费事件绑定 task_id，call_id 为空，每任务最终结算键唯一；底层调用不生成用户扣款分录。
- `wallets`、`vouchers`、`batches`、`price_versions` 保留充值、凭证与价格管理。

钱包可用余额 = 总余额 − 预留；原子事务/条件更新及事件唯一约束防止透支和重复扣款。许可证恢复服务端余额，充值码一次性使用；历史/备份导入不能改写账本，默认不导出 Key 或许可证。

## 状态机与恢复

任务：待估价 → 待确认 → 已预留 → 执行中 → 成功/部分成功/取消/失败/待核账 → 任务结算或补偿释放。用量明细完成不触发独立扣款；满足任务交付和用量条件后才汇总一次结算。

调用：已分配内部预算 → 已发出 → 验证结果/用量 → 已归集或待核账/失败。无独立服务费状态。内部子预算不重复预留钱包。

任务、调用和账本持久化幂等 ID，同 ID 同内容返回原状态，不重复模型请求；同 ID 不同内容拒绝。外部模型请求与数据库事务分离，恢复作业按供应商请求 ID 核查中断/迟到响应，不盲目重发。配置并发、请求限流、单次成本和任务/每日供应商支出上限，不自动增加 V1 调用数。

## 失败、部分成功与补偿

以下与 PRD 第 9 节统一，不按中间调用独立结算：

- 成功任务：可靠可用结果已交付或可按原任务 ID 恢复、相关实际用量可靠，合格成本合计后只收一次服务费。
- 部分成功任务：明确标注可靠可用部分、覆盖范围与失败原因；只纳入实际支持已交付部分且用量可靠的成功调用成本，合计后收一次任务服务费。失败或无交付贡献的调用成本由 GoalClip 承担。
- 无可靠可用交付：失败、超时、无证据、格式无效、取消或后续失败导致无可用结果，整任务扣费 ¥0；即使中间成功或上游已收费，已扣任务 API 费及服务费全额退款。
- 响应丢失或未交付：先按同任务 ID 免费重取，不重新收最低服务费；不可恢复或超过交付截止时间按无交付全退处理。
- 用量未知/不可靠：暂不结算任务，截止前补齐可靠记录后才按任务结算；逾期仍不可靠整任务 ¥0、释放/全退，不以估算替代、不事后追扣。
- 补偿调整：对已结算部分成功任务减少合格成本时，重算剩余任务 API 合计及一次服务费，仅退差额；整任务撤销则全退，调整不新增服务费。

重试/修复不自动纳入 V1；未来批准后也只归集原任务成本，不叠加最低服务费。可靠结果仅在明确短期 TTL 内加密保留最小必要输出，不存完整字幕或敏感对话，不能恢复交付就按规则补偿。核账、交付、退款时限及 TTL 销售前确定，未决时限不改变任务失败基线。

## 后续验收清单（本轮不执行开发）

1. 可解释的任务估价、最高扣费、明确确认；未确认/过期/范围变更未重确认时收费模型请求数为零。
2. 六个单任务示例、缓存 ¥0、同任务两次 ¥0.02 合计 ¥0.14、独立两任务合计 ¥0.24 的规则算例通过；底层拆分不改变同任务最低服务费。
3. 账单展示任务 API 合计、一次服务费、最终扣费，明细展示实际输入/输出/缓存 Token；任务预留及结算不超上限。
4. 可靠部分交付只归集合格成本并收一次服务费；失败无交付、超时、未知用量逾期、上游已扣未交付则任务 ¥0 或全退，补偿不新增最低服务费。
5. 充值重放、并发、中断恢复、迟到回执、重复退款不重复入账/扣费；每任务一个最终结算事件，账本可重建余额。
6. 许可证跨设备恢复，历史导入/导出不收费不改余额，不泄露秘密；保留 G2 身份、证据、缓存、跳转、高亮及旧功能回归要求。
7. 质量优先，关键片段、上下文、理由、覆盖和不确定性由人工样例核查，所有推荐可追溯真实字幕/时间；预算不足不能静默降质。
8. 扩展无开发者 Key、服务端价格防篡改、限流及支出保护有效；Mock 不冒充真实商业链路验证。
9. V1 默认单次 LLM，不新增多调用执行器或三模式 UI；未来能力须另行确认后才进入开发与执行验收。

## 待决策

多调用与三模式是否批准、核账/交付/退款时限、单次/任务/并发/每日上限、汇率与优惠口径、充值有效期与退款渠道、凭证找回、历史备份与账单留存。任务只收一次服务费和第 9 节补偿基线不再作为按调用收费的开放选项。
