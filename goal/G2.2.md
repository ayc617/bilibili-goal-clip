# G2.2 Goal Navigator 引擎

本阶段仅含分析引擎、后台消息、BYOK 适配和测试；不含 UI、Hosted、计费或部署。
MIT 与上游版权声明保持不变。没有新增依赖。

## 调用链

`fetchGoalTranscript({tabId,bvid,page,cid?})` → 原有 B站字幕接口（ASR关闭） → 注册该 tab 的
不可变快照 → `analyzeGoal` → 校验 tab/身份/请求 → 重建快照并验证 SHA-256 → G2.1 本地
检索及宽召回 → 加入邻近 cue/分散取样 → 加载 goal-navigation.md → BYOK adapter → 原有
requestAiCompletion（仅一次） → 严格 JSON/引用验证 → 回填本地证据与站内搜索 URL。

旧 overview/translation/note/explain handler 未改为新 Provider，没有自动触发这些功能。

## G2.3 消息入口

在扩展可信上下文调用，tabId 必须属于实际 B站视频页。每次视频/分P/字幕版本变化重新获取：

```js
const fetched = await chrome.runtime.sendMessage({
  action: 'fetchGoalTranscript', tabId, bvid, page, // cid 可选预期值
});
if (!fetched.success) throw new Error(fetched.error);
const expectedIdentity = {
  ...fetched.snapshot.video,
  transcriptHash: fetched.snapshot.transcriptHash,
};
const requestId = crypto.randomUUID();
const response = await chrome.runtime.sendMessage({
  action: 'analyzeGoal', tabId, requestId, goal: '我想做一个能长期记住用户偏好的 Agent',
  expectedIdentity,
});
```

返回成功：`{success:true,requestId,identity,scope,status:'analyzed',result}`。
空证据返回成功但 `status:'insufficient_evidence',result:null`，不会调用模型。
失败返回 `{success:false,error,requestId?,identity?,message?}`；不要把失败显示成分析结果。

UI 必须在展示前再次比较 requestId 和当前完整 identity，切视频时清除旧结果。后台会在
导航、重载、关闭 tab、重新获取快照和新目标提交时使旧任务失效；请求前后均检查 tab URL
和注册快照。不会自动监控服务器字幕修订：相同 URL 的 CID/字幕静默变化必须通过重新获取
快照同步。后台中断/重启后需重新 fetch；不保证跨 worker 重启的请求幂等。

后台保留至多64条请求记录（满时先淘汰已完成记录）；保留期间相同 tabId/requestId/目标/
身份共享 Promise，错误也不自动重试。同 ID 换目标拒绝。手动重试须新 requestId。
历史记录已淘汰后也应始终使用新 UUID。身份不符或晚到返回 STALE_VIDEO。

## 模块接口及 Provider 契约

CommonJS：`require('./goal/navigator.js')`；浏览器 `GoalNavigator`。

- `identity(snapshot)`：完整身份对象（bvid/cid/page/language/sourceType/provider/transcriptHash）。
- `sameIdentity(a,b)`：比较完整身份。
- `recall(snapshot,goal)`：本地候选及范围元数据，适用于调试。
- `createNavigator({provider,loadSystemPrompt}).analyze({goal,snapshot,requestId,expectedIdentity,getCurrentIdentity})`。
  `getCurrentIdentity` 是异步回调，失效返回 null。引擎不读 Chrome 状态或 Key。

Provider 实现 `complete({task,requestId,identity,messages,maxOutputTokens,outputSchemaVersion})`
返回 `{text,provider,requestId,identity}`。BYOK adapter 只启用 DeepSeek，复用现有模型、Key、
endpoint、响应限制和超时，不返回 settings，也不透传原始服务报错。未来 Hosted 应实现同一
契约，不能把开发者模型 Key 放进扩展。当前不承诺跨服务计费幂等，也未部署 Hosted。

## 模型输入与输出

系统提示词来自 `prompts/goal-navigation.md`。用户消息是 JSON：

```json
{"goal":"用户目标","scope":{"type":"retrieved_candidates","totalCues":100,"suppliedCues":30,"allCuesIncluded":false,"textChars":5000,"missingEvidenceIsNotAbsence":true},"candidates":[{"segmentId":"本地生成ID","text":"原始字幕证据"}]}
```

不将原始 BVID/时间/Key 发给模型。内部 Provider 契约另外携带 identity；BYOK adapter 不会
将 identity 作为模型消息发送。候选 ID 只包含 hash 和局部位置。

模型严格输出 schemaVersion=1：

- goalType: question/task。
- subgoals: 1–5项 `{id:g1..g5,title}`。
- recommendedSegments: 0–8项 `{segmentId,subgoalIds,role,reason}`，通常3–8；证据不足不填充。
- role: direct_answer/prerequisite/method/example/limitation。
- watchOrder: 恰好包含全部推荐 ID，无重复，可与原时间顺序不同。
- coverage: 每个子目标恰好1项 `{subgoalId,status,segmentIds,reason}`。
- status: covered/partial/not_found/uncertain。
- gaps: 最多5项 `{subgoalId,description}`。
- searchKeywords: 最多5项 `{subgoalId,keyword}`。
- limitations: 最多8条。

验证后才回填推荐项的 cueIds/start/end/text。模型多出的 timestamp/text/bvid/url 等字段直接
拒绝；不存在、不在当前候选或跨子目标的证据引用拒绝。covered/partial 必须带支持引用，
covered 至少需 direct_answer/method 角色，不能仅凭 prerequisite/example 标完整覆盖。
这些检查不能证明模型的语义结论正确；仍需真实模型/人工验收。

每项 coverage/gap 增加 `scope:'provided_candidates'`；总结果保留 suppliedCues/allCuesIncluded。
强制增加范围与字幕质量局限说明；常见绝对性全片缺失措辞被保守拒绝，但措辞检查不可能
识别所有表达，UI 也必须展示检索范围，不能把 not_found 解释成全视频不存在。

搜索关键词由程序 encodeURIComponent 后生成固定
`https://search.bilibili.com/all?keyword=...`，附 `verified:false`，不自动访问。

## 规模与召回策略

- 用户目标：1–1000 UTF-16字符；requestId：1–80位字母数字、下划线或连字符。
- 快照：最多50000 cue、2000000原文字符，重建并验证 hash，忽略调用方提供的 segment 映射。
- 候选：最多20个；长视频在预算允许时通常12–20个，证据少/相邻合并/重复/长cue时可更少。
- 复用G2.1 `search(limit:8)`，对原目标及最多8个原文术语分面分别检索，不进行AI扩词。
- 优先高排位命中，再按8个位置区间保留分散命中，适度加入4个位置取样。
- 最多添加前后各1条、间隔不超过5秒的原始cue；已占用cue避免重复挤占。
- 单候选最多2400字符；邻近组合参考1800字符；不切断原cue或插值时间。
- 候选原文合计最多18000字符；系统+用户消息最多28000字符，超限明确失败。
- 输出上限4096 tokens；解析前额外限制48000字符；不是精确输入token计数器。
- 复用50秒无活动、120秒总超时、2MiB HTTP响应上限。任何失败不自动重试/修复。

本地召回分数仅决定候选优先级。最终选择、角色、子目标及watchOrder由一次模型响应给出，
本地只校验引用和结构，不再按时间重排watchOrder。分散范围按cue位置近似，不是真实章节。

## 证据反查

新候选可能合并多条cue，Goal segmentId不是G2.1原始索引segmentId。返回的 `cueIds` 才是
稳定原始引用。用 `GoalTranscriptIndex.createIndex(fetched.snapshot).getEvidence(cueId)`
逐条反查；推荐text等于所含cue按顺序用换行连接，start/end取真实边界最小/最大值。
不应把Goal segmentId直接传给G2.1 getEvidence；它只在该次分析候选集合内有效。
